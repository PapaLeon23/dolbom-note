# 돌봄노트 v3.3 — GitHub Pages + Firebase 무료 배포 안내

이 문서는 **PC에서 처음 설치하는 사람**을 위한 순서입니다. 별도 서버 설치, Node.js, 명령줄이 필요 없습니다.

## v3.3 변경 사항 — 돌봄 용어와 급여 지급 이력

- 화면에 표기하던 **근무** 표현을 **돌봄**으로 통일했습니다(변수명·Firebase 저장 데이터 구조는 유지). 상단 카드에는 `이번 달 완료된 돌봄`과 `이번 달 예정 돌봄`이 **일수·시간**으로 표시됩니다. 자동 완료 판정 및 급여 산식은 변경하지 않습니다.
- 오른쪽 `우리집 돌봄 기준`의 장문 안내 문구를 제거했습니다.
- `급여 지급 현황` 상단에는 **이번 정산기간의 예정 돌봄(일수·시간) 및 예정 금액**을 표시합니다.
- 그 아래 `월별 지급 급여`에 **현재 진행 중인 정산 월을 제외한 직전 6개월/12개월**의 월별 이력을 최신순으로 보여줍니다. 각 월의 정산 시작·종료일, `급여 지급 완료`로 처리된 일수 및 금액을 표시하고, 선택한 기간의 **지급 총액**을 합산합니다. 지급 표시가 없는 월은 0원/지급 기록 없음으로 표시합니다.
- 과거 급여 집계는 **해당 시터의 일정 중 상태가 `paid`인 내역을 월별로 합산**하는 방식입니다. 단순히 오후 8시가 지나 `완료`로 판정된 일정은 지급액에 넣지 않습니다. 사이트에서 송금까지 확인하는 기능은 아니므로 실제 지급 후 관리자가 일정 상태를 `급여 지급 완료`로 변경해야 이력에 반영됩니다.
- 지난 6/12개월의 기준 월은 **한국시간 오늘이 속한 정산기간**입니다. 달력에서 다른 월을 확인하더라도 과거 지급 이력 범위는 변하지 않습니다. 정산 시작일을 변경하면 과거 이력의 귀속 월도 다시 계산됩니다.
- 이번 버전은 **Firestore 데이터 모델과 보안 규칙 변경이 없습니다.** GitHub Pages에서 기존 v3.2를 운영 중이면 `docs/index.html`, `docs/app.js`, `docs/styles.css`만 교체하고 `docs/config.js`는 유지하세요.

## v3.2 화면 및 기능 변경

- **급여 요약 가로 2열**: 왼쪽 `이번 정산기간 예상 급여`, 오른쪽 `근무 완료 급여`. 왼쪽 카드 아래 현재 시급과 실제 정산 시작·종료일이 표시됩니다. 오른쪽 카드에는 완료 근무 급여가 표시됩니다.
- **중복된 정산기간 배너 삭제**: 기존 정산기간 별도 배너를 제거했습니다. 같은 위치에 **오늘의 알림 사항**(아이별 준비물·특이사항)과 **오늘의 투약 요청정보**를 2열 카드로 보여줍니다. 알림이 없으면 `오늘은 별다른 알림 사항이 없습니다.`라고 표시됩니다.
- **근무 상태 요약 변경**: 기존 등록 일수/전체 시간/추가 근무 통계 대신 `완료 근무(일/시간)`와 `예정 근무(일/시간)`를 보여줍니다.
- **투약 요청 관리**: 관리자가 `투약 요청 관리`를 눌러 **아이와 날짜**를 선택하고 투약 시간·약 이름·보호자가 작성한 투약량/방법·추가 메모를 등록합니다. 아이별 하루 최대 10개까지 가능합니다. 저장된 요청은 해당 날짜가 **오늘(한국시간)**일 때만 시터 조회 화면 상단에 표시됩니다. 시터는 읽기만 가능하며 투약량을 자동 계산하지 않습니다. 별도 투약 완료 체크는 이번 버전에 포함되지 않습니다.
- **보안 규칙 업데이트 필수**: Firebase Firestore에 `/medications/{childId}/days/{YYYY-MM-DD}` 경로가 새로 추가됩니다. 시터 계정은 배정된 아이에 한해 문서 하나씩 직접 조회할 수 있고, 작성·수정·삭제는 관리자만 할 수 있습니다.

**이미 GitHub Pages에서 v3.1을 운영 중이라면:** 새 압축의 `docs/index.html`, `docs/app.js`, `docs/styles.css`를 기존 저장소에 업로드하여 교체합니다. 현재 사용 중인 `docs/config.js`는 **교체하지 마세요**(Firebase 연결값 유지). **Firebase 콘솔의 Firestore Database → Rules에서 새로운 `firestore.rules` 전체를 다시 게시해야** 투약 요청을 저장하거나 시터가 읽을 수 있습니다. 마지막으로 브라우저에서 Ctrl+Shift+R로 새로고침합니다. 실제 Firestore의 기존 시터/일정/전달사항 데이터는 유지됩니다.

## v3.1 수정: 급여 요약 한눈에 보기

관리자·시터 화면의 첫 번째 요약 카드에 **이번 정산기간 예상 급여**와 **현재까지 완료 근무 급여**를 동시에 보여줍니다.

- **예상 급여** = 선택한 정산기간에 등록된 근무 일정 전체(예정 + 완료 + 지급 완료)의 시간 × 날짜별 시급
- **완료 근무 급여** = 같은 정산기간 중 **근무 완료** 또는 **지급 완료**로 판정된 일정만 합산
- **완료율** = 완료 근무 급여 ÷ 예상 급여. 아직 일정이 없으면 0%입니다.
- 매일 한국시간 오후 8시 이후 예정 근무가 자동으로 완료로 판정되므로 완료 금액과 진행률이 자동으로 올라갑니다.
- **예상 급여는 확정 청구액이 아닙니다.** 근무표 변경·추가 근무에 따라 언제든 달라질 수 있습니다. 지급 완료 여부는 기존 급여 지급 현황에서 구분됩니다.
- '이번'은 화면에서 선택한 **정산 월**을 뜻합니다. 26일 시작 설정이라면 예: 11월 정산 = 10월 26일~11월 25일.

**이미 v3 사이트를 GitHub Pages에 게시했다면:** 새 파일의 `docs/index.html`, `docs/app.js`, `docs/styles.css`만 기존 저장소의 동일 경로에 덮어써도 됩니다. 실제 입력한 `docs/config.js`는 **덮어쓰지 마세요.** 이번 수정은 Firebase 데이터 구조와 보안 규칙을 바꾸지 않습니다. 갱신 후 브라우저를 강력 새로고침(Ctrl+Shift+R)하세요.

## 무엇이 구현됐나요?

- 관리자는 **시터 계정 UID(Firebase Authentication ID)** 를 등록하고 해당 계정에 **첫째/둘째를 각각 배정/해제**할 수 있습니다. 여러 시터도 각자 시급과 근무표가 분리됩니다.
- **시터별 시급**과 시급 **적용일**을 관리합니다. 예: 11월 1일부터 15,000원 → 16,000원으로 변경하면 이전 날짜는 이전 시급으로 계산합니다.
- 매월 정산기간 시작일 설정: 매월 26일~다음 달 25일 / 21일~다음 달 20일 / 1일~말일 등. 정산 월은 종료일이 속한 달로 표시됩니다.
- 기본 근무 **16:30~18:30(2시간)**. 추가 근무는 30분 단위. 아이 두 명을 동시에 돌봐도 **아이 수를 곱해 계산하지 않습니다**.
- **아이별 전달사항**: 관리자가 날짜, 병원/키즈카페 예약 등의 특이사항, 준비물을 입력하면 배정된 시터의 화면 최상단에 표시합니다. 과거 날짜의 전달사항은 자동 숨김 처리합니다. 현재 아이별 **예정 전달사항 1건**을 관리하며 화면의 오늘 알림 영역에는 해당 날짜가 오늘인 경우만 표시합니다.
- **오후 8시 자동 근무 완료**: 등록된 일정은 근무일의 **한국시간 20:00** 이후 자동 완료로 보이고 급여에 반영됩니다. 서버에 시간을 맞춰 쓰기 작업을 예약하는 대신 **화면이 열렸을 때 계산하는 방식**입니다. 웹페이지가 열려 있는 경우 1분 이내 갱신됩니다. 관리자는 휴무/취소 시 반드시 일정 삭제, 지급 후에는 **지급 완료**로 표시합니다.
- CSV 급여 다운로드와 시터 조회 전용 로그인 기능. 실제 송금, 자동 문자·알림, 세금·주휴수당 계산은 포함되어 있지 않습니다.

## 0. 준비물

- GitHub 계정: https://github.com/
- Google 계정: https://console.firebase.google.com/
- 압축 해제한 이 프로젝트 폴더. **사이트 파일은 `docs/` 안에 있습니다.**
- **공개 저장소를 만들게 되므로 자녀 실명/주소/비밀번호는 소스코드에 절대 작성하지 마세요.** 자녀 이름과 전달사항은 사이트 관리자 로그인 이후 Firestore에 입력하세요.

## 1. Firebase 프로젝트 만들기

1. **https://console.firebase.google.com/** 에 접속해 **프로젝트 추가**를 선택합니다.
2. 프로젝트 이름 예시 `dolbom-note-family`. Google Analytics는 필요 없다면 비활성화해도 됩니다.
3. **Spark 무료 요금제** 유지(유료 Blaze로 변경할 필요 없음).
4. 프로젝트 개요 옆 **톱니바퀴 → 프로젝트 설정 → 일반 → 내 앱 → 웹(</>)** 을 등록합니다. 앱 닉네임은 `dolbom-note` 등으로 설정합니다.
5. **SDK 설정 및 구성 → 구성(Config)** 에서 다음 항목을 확인합니다.

```javascript
const firebaseConfig = {
  apiKey: "....",
  authDomain: "프로젝트ID.firebaseapp.com",
  projectId: "프로젝트ID",
  appId: "1:....:web:...."
};
```

6. 압축을 풀어 `docs/config.js`를 메모장으로 열고 해당 네 값만 복사해 넣고 저장합니다. 다른 코드는 그대로 두세요.

```javascript
window.SITTER_FIREBASE_CONFIG = {
  apiKey: "복사한_apiKey",
  authDomain: "복사한_authDomain",
  projectId: "복사한_projectId",
  appId: "복사한_appId"
};
```

> `apiKey`는 Firebase 웹앱에서 공개 사용을 전제로 하는 식별자입니다. 보안은 아래 Firestore 규칙과 사용자 인증으로 유지합니다. **비밀번호, 서비스 계정 JSON, 서버 비밀키 등은 절대 GitHub에 올리지 마세요.**

## 2. Firebase 로그인과 데이터베이스 설정

1. Firebase 콘솔 왼쪽 메뉴 **Authentication → 시작하기 → Sign-in method → 이메일/비밀번호** 를 켜고 저장합니다.
2. **Authentication → Users(사용자) → Add user**에서 **관리자용 계정 1개**, **시터님 계정 1개**를 각각 이메일/비밀번호로 만듭니다. 인증 정보는 별도로 안전하게 전달합니다.
3. 두 계정의 **UID**를 복사해 둡니다. UID는 이메일이 아니라 Firebase에서 자동 발급한 영숫자 ID입니다.
4. **Firestore Database → 데이터베이스 만들기**를 선택합니다. **Standard 에디션 / (default) 데이터베이스 / 가까운 위치(예: 서울) / 프로덕션 모드**를 선택합니다. **테스트 모드로 운영하지 마세요.**
5. **Firestore Database → Rules(규칙)** 메뉴에서 이 폴더 최상단의 `firestore.rules` 내용을 **전체 복사·붙여넣기** 하고 **게시(Publish)** 합니다. 초기 프로덕션 규칙은 전면 접근 차단이라 게시 전에는 로그인 후 조회가 되지 않습니다.
6. **Firestore Database → Data(데이터)** 메뉴에서 `roles`라는 컬렉션을 만듭니다. 각 계정의 UID를 문서 ID로 입력해 다음 두 문서를 만듭니다(콘솔의 `+ 문서 추가` 사용).

| 컬렉션 | 문서 ID | 필드 이름 | 필드 유형 | 값 |
|---|---|---|---|---|
| `roles` | 관리자 계정의 UID | `role` | **string** | `admin` |
| `roles` | 시터 계정의 UID | `role` | **string** | `sitter` |

**예시:** 관리자 UID가 `abc123...`이면 `roles/abc123...` 문서의 필드 `role`을 문자열 `admin`으로 입력합니다. `roles/`에 이메일 주소를 문서 ID로 쓰면 안 됩니다.

> Firebase 콘솔에서는 관리자 권한으로 규칙과 무관하게 위 문서를 만들 수 있습니다. 일반 웹 사용자는 이 `roles` 컬렉션의 문서를 수정할 수 없습니다.

## 3. GitHub에 사이트 올리기 — 명령어 없이

1. **https://github.com/** 로그인 → 우측 상단 `+` → **New repository**.
2. Repository name에 예: **`dolbom-note`** 입력.
3. **Public(공개)** 선택. GitHub Free에서 무료 GitHub Pages를 사용하기 위한 설정입니다. **공개되는 것은 소스코드이지 Firebase 로그인으로 보호되는 실제 근무 데이터가 아닙니다.**
4. `Create repository` 클릭.
5. 저장소 화면에서 **Add file → Upload files** 선택.
6. 압축을 풀어 생긴 `docs` 폴더와 `README.md`, `firestore.rules`를 업로드 화면으로 **드래그해서 업로드**하세요. `docs` 디렉터리 구조가 유지되어야 합니다. GitHub 웹 업로드는 폴더 드래그를 지원합니다.
7. 아래쪽에서 `Commit changes` 버튼을 누릅니다.
8. 저장소의 **Settings → Pages**로 이동합니다.
9. **Build and deployment → Source: Deploy from a branch → Branch: main → Folder: /docs → Save**.
10. 발급된 URL로 접속합니다. 형태는 대체로 다음과 같습니다.

```text
https://본인GitHub아이디.github.io/dolbom-note/
```

> `username`과 저장소 이름이 실제 주소를 결정합니다. 공개 직후 연결이 반영될 때까지 잠시 차이가 있을 수 있습니다. GitHub에서 **Settings → Pages**에 표시되는 **실제 URL**을 사용하세요.

### 권장: Firebase 승인된 도메인

**Firebase → Authentication → Settings → Authorized domains**에서 `본인GitHub아이디.github.io` 도메인이 등록돼 있는지 확인하고, 없다면 추가하세요(경로 명칭은 바뀔 수 있습니다). 도메인에는 `/dolbom-note/` 경로를 넣지 않습니다. 이메일/비밀번호 로그인은 승인 도메인 제한과 관계없이 작동하는 경우도 있지만, 향후 인증 기능을 추가할 경우를 위해 지정하는 것이 좋습니다.

## 4. 처음 접속한 뒤 관리자 화면에서 할 일

1. 위 GitHub Pages URL을 열어 **관리자 이메일/비밀번호**로 로그인합니다.
2. `설정`에서 두 아이의 호칭과 정산 시작일(기본 26일)을 저장합니다.
3. `시터·아이 관리` 클릭 → **시터 UID**에 Firebase Authentication에서 복사한 시터 계정 UID 입력.
4. 시터 이름/호칭, 시급 **15,000원**, 적용일 입력 → 첫째/둘째 체크 → **연결 저장**.
5. **월 근무표 만들기** → `정산기간 전체` 선택 → 월~금 등 근무 요일 선택 → 생성. 이미 등록된 날짜는 건너뜁니다.
6. 30분 추가 근무 날짜는 달력을 눌러 `하원 + 추가 근무`를 선택합니다.
7. `전달사항 관리`에서 아이별로 **예정 날짜 / 특이사항(병원·예약 등) / 준비물** 입력.
8. `투약 요청 관리`에서 **아이 / 투약 날짜 / 시간 / 약 이름 / 보호자의 투약 방법**을 입력하고 `요청 목록에 추가`를 누른 뒤 반드시 `투약 요청 저장`을 누릅니다.
9. 시터님에게 **같은 URL과 시터용 계정**만 전달합니다. 시터님은 읽기 전용으로 일정과 자신에게 매핑된 아이의 전달사항을 볼 수 있습니다.

## 5. 급여 및 오후 8시 자동 완료 계산

### 급여 산식

| 일 근무 유형 | 시간 | 시급 15,000원 기준 |
|---|---|---:|
| 하원 | 16:30 ~ 18:30 | 30,000원 |
| 하원 + 30분 | 16:30 ~ 19:00 | 37,500원 |
| 하원 + 60분 | 16:30 ~ 19:30 | 45,000원 |

급여 화면의 **현재까지 근무 완료 급여**는 `근무 완료 + 지급 완료`의 합계이며, **예상 급여**는 예정 근무까지 합친 전체 등록 일정 금액입니다. `근무 예정`은 따로 표시하고 합산하지 않습니다. 매일 한국시간 오후 8시 이후 해당 날짜의 `근무 예정`이 **표시상 `근무 완료`**로 처리되고 계산에 포함됩니다. 이 판정은 클라이언트가 날짜/시간을 읽어 수행하며 **서버 기록을 20:00 정각에 강제로 바꾸는 기능은 아닙니다**. 이모님이 그날 근무하지 않았다면 관리자가 **일정을 삭제하거나 수정**해야 합니다. 이미 `지급 완료`로 지정한 날짜는 그대로 유지됩니다.

### 정산기간

예를 들어 **2026년 11월 급여**의 대상 기간은 다음과 같습니다.

| 매월 정산 시작일 | 산정되는 근무일 |
|---|---|
| 26일 | 2026-10-26 ~ 2026-11-25 |
| 21일 | 2026-10-21 ~ 2026-11-20 |
| 1일 | 2026-11-01 ~ 2026-11-30 |

시급 변경 시 **시터·아이 관리 > 변경 시급 적용일**을 정확히 설정하세요. 이력에 날짜별 시급을 보유하므로 적용일 이전 급여는 유지합니다. 정산 시작일 변경은 과거 급여의 귀속 월까지 바뀌므로 기존 정산 CSV를 먼저 보관하는 것이 좋습니다.

## 6. 수정 후 업데이트 방법

1. 로컬 `docs/` 안의 소스파일을 수정합니다. **GitHub 저장소의 `docs/`에 같은 파일을 다시 업로드/커밋**하면 GitHub Pages가 다시 게시합니다.
2. Firebase 설정을 고친 경우 `docs/config.js`도 업로드합니다.
3. **Firestore 보안 규칙을 변경했다면 GitHub 업로드만으로 적용되지 않습니다.** Firebase 콘솔 → Firestore Database → Rules에서 바뀐 `firestore.rules`를 다시 게시해야 합니다.
4. 근무표·아이 이름·메모·시급 같은 운영 데이터는 앱에서 수정합니다. 소스코드에는 쓰지 마세요.

## 7. 주의사항·문제 해결

- **체험판은 다른 기기와 동기화되지 않습니다.** `돌봄노트_v3_체험판.html`은 기능 테스트용이고, 데이터는 해당 브라우저의 저장소에 남습니다.
- **관리자로 로그인했는데 시터 목록이 비어 있음:** `roles` 문서가 맞는지, 시터 역할(`role='sitter'`) 문서를 만들었는지, 관리자에서 `시터·아이 관리`를 실행했는지 확인합니다.
- **로그인 후 권한 미설정 표시:** `roles/{UID}` 문서 ID 또는 `role` 필드의 오타를 확인합니다.
- **시터에게 오늘의 알림이 안 보임:** UID 매핑이 돼 있는지, 해당 아이에 체크했는지, 전달사항 날짜가 **오늘**인지 확인합니다.
- **시터에게 투약 요청이 안 보임:** 투약 날짜가 오늘인지 확인하고 새로운 `firestore.rules`가 게시되었는지, 연결된 아이인지 확인합니다.
- **시터 근무표가 안 보임:** 보안 규칙이 최신인지, `sitters/{UID}`가 등록됐는지 확인합니다.
- **체험 모드가 뜸:** `docs/config.js` 필수 4개 값이 비어 있으면 체험 모드로 동작합니다. Firebase 연결값을 채우고 GitHub에 다시 업로드하세요.
- **GitHub Pages 화면이 안 열림:** 저장소의 `docs/index.html` 파일이 있는지, Pages 설정을 `main`·`/docs`로 했는지 확인합니다.
- **Firestore 무료 한도:** Spark 요금제에 무료 사용량 제한이 있고 초과하면 사용이 제한될 수 있습니다. 이용자는 소수인 가족 용도라 일반적으로 무료 범위 내로 예상하지만 무제한 보장은 아닙니다.
- **아이 개인정보:** 알레르기·진료·연락처 등 민감할 수 있는 정보는 필요한 범위에서만 기록하고, 시터 계정 비밀번호 유출 시 Firebase Authentication에서 계정을 비활성화/비밀번호 재설정하세요. 접근 차단은 `시터·아이 관리`에서 체크를 해제하거나 `roles/{UID}` 권한을 제거하세요.
- **v2 데이터 호환성:** v3는 시터별 데이터 분리를 위해 `sitters/{UID}`와 `schedules/{UID}__{날짜}` 구조를 사용합니다. **이미 Firebase에서 v2를 운영 중이면 기존 Firestore 근무 일정은 자동 마이그레이션되지 않습니다.** 기존 데이터를 CSV로 보관하고 마이그레이션한 뒤 v3를 전환하세요. 체험판의 같은 브라우저에 남아 있는 v2 로컬 데이터는 일부 자동 가져옵니다.
